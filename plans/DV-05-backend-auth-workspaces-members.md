# DV-05 — Backend API: auth, workspaces, members

**Status:** implemented and verified on 2026-09-20 (branch `user-management`, uncommitted).

## Goal
Implement the first slice of `PRD/10-api-specification.md`: **Auth** (register, login, logout, me), **Workspaces** (list, create, get, delete) and **Members** (list, change role, remove, transfer ownership). Invites and invite acceptance are deferred (no email delivery exists to carry the invite link).

## Decisions
- Scope: auth + workspaces + members (chosen by the user).
- Access token: HS256 JWT, **24 hours** (`JWT_EXPIRE_MINUTES`, default 1440), **no refresh flow**. A longer lifetime means a leaked token is useful for longer, which is why logout revokes server-side.
- **Logout revokes the token server-side**: every token has a random `jti`; `POST /auth/logout` stores it in the new `revoked_tokens` table; every authenticated request rejects a listed `jti`. Other tokens of the same user stay valid. Expired rows are purged on each logout.
- Tests run against a real PostgreSQL, in an **auto-created `<db>_test` database** on the server `DATABASE_URL` points at.
- Ownership transfer only to an existing **Admin** (PRD 05); the Owner becomes an Admin in the same transaction.
- No RLS or triggers exist yet, so `api/deps.py` plus tests are the only enforcement of tenant isolation and the one-owner rule.

## Deviations from the plan
- The test database is created on whichever server `.env` points at. Here that is the Windows-installed PostgreSQL on port 5432 (the same server as the dev `docvault` database), not the Docker container on 5433. Only a new `docvault_test` database was created there.
- Argon2 uses minimal cost in API tests only (`fast_password_hashing` fixture); production parameters are untouched and `test_security.py` covers them.
- The API tests use a small connection pool per test instead of `NullPool` (half the run time).

- Backend: `ruff check`, `ruff format --check`, `mypy app` (strict, 40 files) clean; **229 tests pass** (37 s), including the migration applied to a fresh database and `alembic check` (models match migrations).

- Migration reviewed offline (`upgrade ... --sql`, `downgrade ... --sql`): one table, unique `jti`, two indexes, clean downgrade, single head.
- Frontend: `lint`, `tsc -b`, `build`, `prettier --check` clean; **54 of 54 tests**.
