# DV-03 — Alembic environment setup and model definitions

**Status:** implemented and verified (branch `amol`, merged before this record was written; re-verified on 2026-09-22 from `share-link-activity-document-invites`).

## Goal
Define the full SQLAlchemy 2 (async) model layer per `PRD/04-database-schema.md` and wire up Alembic so the schema is reproducible from a single initial revision. No routes or services yet — this is the data layer only.

## What was built
| Area | Result |
|---|---|
| Models | `users`, `workspaces`, `workspace_members`, `folders`, `folder_grants`, `documents`, `document_versions`, `share_links`, `activity_log` — declared in `app/models/{user,workspace,folder,document,share_link,activity}.py`, `app/models/enums.py` for role/status enums, `app/models/__init__.py` re-exporting the mapped registry |
| IDs & mixins | `app/core/ids.py` (opaque random id generation), shared `TimestampMixin` / id-column helpers in `app/db/base.py` |
| Migration | Single autogenerated initial revision (`backend/alembic/versions/2026_09_20_0452-bba684a776e9_initial_revision.py`) covering every table, constraint and index in PRD 04 |
| Alembic | Async `env.py` wired to the app's engine/settings, `backend/alembic/README.md` documenting the workflow, `alembic.ini` adjusted for the project layout |
| Config | `app/config.py` gained the DB/storage settings needed to run migrations; `.env.example` kept in sync |
| Docs | `PRD/04-database-schema.md` filled in to match the final column/constraint set (was a draft before); `PRD/docvault-erd.drawio` added; `PRD/09-project-structure.md`, `PRD/README.md` updated |
| Tests | `backend/tests/test_models_metadata.py` — asserts every table/column/constraint/index declared in PRD 04 is present on the mapped metadata, so a model change without a matching migration (or vice versa) fails immediately |
