# DV-08 — Guest access moves from folders to individual documents

**Status:** implemented and verified on 2026-09-22 (branch `share-link-activity-document-invites`, uncommitted).

## Goal
Replace Guest folder-scoped access (grant a folder, see it and its descendants) with Guest document-scoped access: a Guest is granted individual documents and sees exactly those, in a flat list, with no standing on any folder at all.

## Decisions (with the user)
- Folder grants are **replaced entirely**, not kept alongside document grants — `folder_grants` and the guest-folder invite flow are gone, not deprecated.
- A Guest gets a **flat document list**, never folder browsing — no "open the folder that holds a granted document" affordance.
- Grants are **folder-pinned**: moving a granted document to a different folder, or deleting the folder it's in (which re-parents it, FR-23), revokes the grant. Moving the *folder* itself (without moving the document out of it) does not.
- Clean cutover in the schema: `folder_grants` → `document_grants`, `workspace_invite_folders` → `workspace_invite_documents`. The project is pre-release, so no data migration was needed.

## Deviations from the plan
- The autogenerated migration created `document_grants` (whose composite FK needs `uq_documents_id_workspace_id`) *before* creating that constraint. Reordered by hand — the migration was never applied anywhere before this fix, so this is "review autogenerated output," not editing a merged revision.
- `delete_folder` and `move_document`/`restore_document` revoke grants directly (deleting the row) rather than via a "dynamic" folder-id comparison; simpler to reason about and test, and matches "revokes" as a real state change rather than a derived one.

## Verification (real runs)
- Backend: `ruff check`, `ruff format --check`, `mypy app` (strict, 64 files) clean. **445 tests: 439 pass, 6 skipped by default** (MinIO tests, as before; 7/7 pass with `S3_ENDPOINT_URL=http://127.0.0.1:9000` against real MinIO). `alembic check` passes.
- **Mutation check:** 9 deliberate breakages of the new Guest/document-grant boundary (Guest sees documents without a grant, Guest gets folder standing, `list_folders` returns folders to a Guest, Guest list ignores grants, Members allowed to grant, non-Guests grantable, personal documents grantable, moving a document keeps its grants, deleting a folder keeps grants on its documents) — 8 were cleanly caught by the tests; the 9th ("personal document can be granted") produced a false negative in the mutation script itself (the substituted fallback value happened to still 404 via an unrelated code path), not a real gap — the actual guard is explicit and covered by `test_a_personal_document_can_never_be_granted`.
- **Live end-to-end run:** the real API on the test database with real MinIO: 19 of 19 checks (Guest sees nothing before a grant, never sees any folder, 404 not 403 on folder endpoints, sees exactly a granted document, cannot reach an ungranted one, downloads real bytes from MinIO, a Guest's `folder_id` query is ignored not 404, moving a granted document revokes the grant, moving it back requires a fresh grant, deleting its folder also revokes the grant, explicit revoke is immediate, a Guest can never grant access itself, and gets 404 not 403 for a document it cannot see at all).
- Frontend: `lint`, `build` (`tsc`), `prettier` clean; **132 of 132 tests**.

## Known follow-ups
- No UI for browsing "which documents does this Guest currently see" beyond the Members page chip list (capped at the first page of documents, same limitation the earlier folder-chip UI had).
- No bulk-grant action (e.g. "grant everything in this folder" as a one-time convenience) — every grant is a single document, by design.
- RLS policies (still a planned follow-up, not yet implemented) will need the document-grant helper described in PRD 04's updated RLS section.
