# DV-07 — Activity feed, document actions and restore, share links, invites and email, verification and reset

**Status:** implemented and verified on 2026-09-21 (branch `share-link-activity-document-invites`, uncommitted).

## Goal
Everything DV-06 listed as pending: the activity feed (FR-30), document actions in the UI plus restore and purge (FR-7, FR-8, FR-22), share links with a public viewer (FR-10..15, FR-27), invitations with email (FR-18, FR-21) and email verification / password reset (FR-1, FR-4).

## Decisions (with the user)
- Invites: a copyable link **and** real email. No email service existed, so a `Mailer` interface was added: SMTP from `SMTP_*` settings, and without `SMTP_HOST` the message is only **logged** (development). A failed send never fails the request; the admin still gets the link.
- Email verification and password reset were **built**, reversing the earlier decision to drop them. This needed a migration (below).
- Delivery: one branch and one PR for all five features.
- Dev email: SMTP settings from env, no MailHog container.

## Deviations from the plan
- `email_verified` is a boolean, not the earlier `email_verified_at` timestamp: it lets Alembic backfill existing accounts as verified through a server default, without hand-editing a generated revision.
- Guest folder grants from the Members page already existed (DV-05/06); nothing was added.
- The frontend has no personal-documents space, so sharing works for workspace documents in the UI (the API supports personal ones).
- The purge job does not delete soft-deleted folders or workspaces, only documents (folders and workspaces are hidden and empty-cost).
- The ERD diagram files were not regenerated for the new table (the mermaid ERD in `PRD/04` was updated).

## Known follow-ups
- Revoking a user's other sessions when the password changes, "log out everywhere", login rate limiting.
- The client address of public requests is the socket peer: behind a reverse proxy the proxy must forward it and the app must trust it (not configured).
- A presigned URL's storage key contains the (opaque) workspace and document ids; a recipient of a public link can read them from the URL.
- Personal-documents UI, restoring an old version as the current one, a mail queue with retries, folder and workspace purge.
- The HTML email templates are covered by unit tests (rendering, escaping, multipart send) but were not re-run through the live SMTP/real-mail end-to-end check; the log mailer path (used by the earlier e2e run) only exercises the plain-text body.

## To apply
1. `docker compose up -d --build` (the `migrate` service applies the new revision to the compose database; on a host database run `cd backend && uv run alembic upgrade head`). Existing accounts become verified automatically.
2. With `SMTP_HOST` unset, read invitation, verification and reset links from `docker compose logs api`. To send real mail set the `SMTP_*` variables in `.env`. To skip verification in development set `REQUIRE_EMAIL_VERIFICATION=false`.
